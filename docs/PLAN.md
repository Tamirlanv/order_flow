## Правило выполнения

Каждый пункт — отдельный законченный этап в feature-ветке с коммитом после проверок и обновления документов, затем merge `--no-ff` в `main` и push обеих веток. Перед существенной функцией создать или уточнить спецификацию в `docs/features/`; затем реализация → тесты → исправления → просмотр diff → документация → коммит. Если этап разрастается или часть проверок недоступна, выделить проверяемую часть явно. Следующий этап не требует повторного подтверждения.

## Минимум перед каждым коммитом

1. Посмотреть `git status --short`; отделить чужие изменения.
2. Выполнить доступные проверки затронутой функции и обязательные общие проверки.
3. Просмотреть diff, обновить спецификацию/README/этот план.
4. Добавить только файлы этапа; просмотреть `git diff --cached` и `git diff --cached --check`.
5. Сделать коммит в feature-ветке, merge проверенной части в main и push в origin без force. Проверить результат Git и CI, если он доступен.

Команды pytest/lint/build добавлены на M01a и описаны в README. Общий локальный запуск — `./scripts/check.ps1`. Наличие строки в плане не означает существующий тест бизнес-функции.
