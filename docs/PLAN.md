## Правило выполнения

Каждый пункт ниже — отдельный законченный этап с локальным коммитом после проверок и обновления документов. Перед существенной функцией создать или уточнить спецификацию в `docs/features/`; затем реализация → тесты → исправления → просмотр diff → документация → коммит. Если этап разрастается, разделить его в этом плане до продолжения. Следующий этап не требует повторного подтверждения, когда пользователь разрешит реализацию; текущий запрет на запуск контейнеров сохраняется до отдельного изменения.

## Минимум перед каждым коммитом

1. Посмотреть `git status --short`; отделить чужие изменения.
2. Выполнить доступные проверки затронутой функции и обязательные общие проверки.
3. Просмотреть diff, обновить спецификацию/README/этот план.
4. Добавить только файлы этапа; просмотреть `git diff --cached` и `git diff --cached --check`.
5. Сделать локальный коммит с содержательным сообщением. Не push.

До M01 нет команд pytest/lint/build: они должны появиться вместе с кодом и зависимостями. Наличие строки в плане не означает существующий тест.
