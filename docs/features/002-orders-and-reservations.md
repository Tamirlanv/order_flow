# Заказы и резервирование

Статус: проект, реализация не начата. Этапы M04a–M04c. Требования BR-01…06, AC-03…06, AC-09.

## Успешный сценарий

Клиент вызывает `POST /api/v1/stores/{store_id}/orders` с позициями, контактами и `Idempotency-Key`. Для партнёра проверяется API-ключ; публичная витрина имеет отдельный guest endpoint без права произвольно управлять магазином. Цена берётся из БД, дубликаты SKU в запросе объединяются с проверкой общего количества.

Система одной транзакцией создаёт awaiting_payment заказ и резерв всех позиций на 15 минут. Ответ 201 содержит заказ и дедлайн; гостевой секрет выдаётся покупателю, в БД хранится только его hash. Не передавать гостевой секрет в обычных query-логах; интерфейс принимает его через fragment ссылки и использует для последующих защищённых запросов.

## Ошибки и конкуренция

Невалидное количество — 422; неизвестный/архивный SKU — понятная ошибка без раскрытия чужих данных; недостаточный остаток — 409 с доступными для данного магазина позициями. Вся транзакция откатывается. Повтор ключа и тела возвращает исходный заказ, изменённое тело — 409.

Идемпотентность гостя ограничена магазином и серверной гостевой сессией, партнёра — магазином и ключом API. До первого заказа витрина получает HttpOnly гостевую сессию с защитой изменяющих запросов от CSRF. Повтор не должен раскрывать гостевой доступ другому клиенту. Ответ с гостевым секретом хранится в IdempotencyRecord зашифрованным (AEAD, отдельный ключ окружения, область магазина и операции в authenticated data) в течение 24 часов и возвращается только той же гостевой сессии. В Order остаётся только hash секрета. После истечения срока идемпотентности зашифрованный ответ удаляется.

Блокировки остатков берутся в одинаковом порядке. Оплата/отмена/истечение блокируют Order; переходы терминального заказа повторно не применяются. Истечение проверяет время сервера в транзакции, не время доставки Celery-задачи.

## Приёмка и тесты

- При 50 параллельных заказах с остатком 1 успешен ровно один.
- Ошибка второй позиции не оставляет резерв первой.
- Повтор ключа возвращает тот же заказ; параллельный повтор не создаёт дубль.
- Изменение цены товара не меняет сумму существующего заказа.
- Отмена и повтор отмены освобождают reserved один раз.
- Планировщик освобождает просроченное в течение 60 секунд при работающем стенде; после простоя обрабатывает накопленное.
- Гонка оплаты и истечения имеет один результат по правилу дедлайна, не создаёт отрицательных остатков.
