# S01 — проверка безопасности и Nginx

Статус: текущие функции исправлены и проверены локально; CI предстоит. Пункт цены остаётся открытым до M03a. Ветка `feature/security-hardening`. По запросу пользователя выполняется перед M02b; связь — требования безопасности и BR-03/BR-11.

## Границы и поведение

Проверяем существующие аккаунты и локальный Compose. Публичное развёртывание не выполняется. Nginx остаётся единственной опубликованной точкой входа приложения. Добавляются CSP, X-Frame-Options, безопасное проксирование, ограничение тела auth-запросов и журнал без URL, query, IP, cookies и тела запроса. Swagger поставляется локально, без CDN и inline JavaScript.

Опциональный HTTPS-режим использует локальный сертификат, созданный вне Git. HSTS выдаётся только при TLS; тест проверяет сертификат через явный CA-файл, без verify=False. Самоподписанный сертификат автоматически не добавляется в доверенные ОС/браузера. Обычный HTTP-режим сохраняется для локальной разработки.

Все текущие изменяющие действия (регистрация, вход, повтор письма, подтверждение email, выход) требуют привязанного к cookie CSRF-токена и точного Origin. В SPA токен передаётся заголовком X-CSRF-Token, скрытое HTML-поле не требуется. Тесты должны проверять каждое действие, включая кнопки вне form.

Лимит входа — 10 попыток за 15 минут на нормализованный email, дополнительно 20 на IP. Клиентский X-Forwarded-For не считается достоверным. Проверяем изменение заголовка, регистра email, cookies и реального адреса подключения.

Каталог, SKU и API записи цен ещё не реализованы. Пункт проверки цены остаётся открытым до M03a: серверная валидация Decimal > 0 и PostgreSQL CHECK(price > 0), создание и изменение, ноль/отрицательная/нечисловая цена, точность 2 знака. Отсутствующий endpoint или тестовая заглушка не считаются доказательством защиты. Тест явно пропускается до появления каталога и требует реализации при появлении модели цены.

## Критерии приёмки

1. Каждый текущий mutating endpoint отказывает без CSRF, с чужим токеном/cookie/Origin; успешные сценарии сохраняются. Frontend-тесты подтверждают передачу токена всеми формами/кнопками.
2. Nginx возвращает CSP и X-Frame-Options на UI, API, документации и ошибках; HTTPS дополнительно HSTS и Secure cookies. HTTP не притворяется защищённым HSTS. UI и API-документация работают с CSP.
3. 11-я попытка входа в один аккаунт даёт 429 даже при подмене X-Forwarded-For/регистра email/сессии и смене адреса. Другой аккаунт ещё получает 401, доказывая срабатывание именно лимита аккаунта.
4. Проверка цен имеет честный статус «не применимо: M03a не реализован»; критерии M03a дополнены. Не закрывать этот пункт успешным тестом неиспользуемого валидатора.
5. Скрипт проверяет имена и точные версии всех Python/npm пакетов из lock-файлов в PyPI/npm, включая транзитивные/необязательные. Сетевые ошибки дают сбой проверки. Существование пакета не означает его безопасность; отдельно выполняются npm audit и pip-audit.
6. Gitleaks с redaction проверяет всю доступную Git-историю/ветки и текущее содержимое tracked-файлов. Секреты и локальные .env/сертификаты не коммитятся; запрещены широкие исключения ради зелёной проверки.
7. Повторяемые проверки входят в CI. В `logs/security/` сохраняются Markdown-отчёты: доказательство, риск, исправление, команда, фактический результат, ограничения. Не более 100 проблем на файл; не выдумывать проблемы для количества.

## Проверки и остановка

Unit/API + PostgreSQL/Redis + реальные HTTP/TLS-запросы через Nginx, UI-тесты, сетевые проверки реестров, сканирование секретов. До и после исправлений фиксировать фактический результат. Полный аудит будущих бизнес-модулей, pentest и публичный production-стенд не входят в этот этап.
