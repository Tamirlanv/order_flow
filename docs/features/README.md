# Спецификации функций

Спецификация появляется **до** реализации существенного поведения. Документы здесь уточняют [ТЗ](../REQUIREMENTS.md), но не заменяют его. Изменение границ MVP отражать также в ТЗ и [плане](../PLAN.md).

Подготовлены для просмотра:

- [001 — магазины, роли и изоляция](001-stores-and-access.md).
- [002 — заказы и резервирование](002-orders-and-reservations.md).
- [003 — восстановление пароля](003-password-reset.md).

Новые документы именовать `NNN-short-feature-name.md`. Перед реализацией входа, подтверждения email, приглашений, импорта, оплаты и доставки добавить их подробные спецификации.

Шаблон:

```markdown
# Название
Статус: проект / согласовано / в работе / реализовано, проверено.
Связь: этап плана, AC/BR из ТЗ.
## Цель и пользователи
## Успешный сценарий
## Ошибки, конкурентные действия и права
## Данные и API-контракт
## Проверяемые критерии приёмки
## План тестов
## Ограничения и исключения
## Фактические проверки
```
